## (b) Owner guidance, verbatim (outranks everything below it)

> **Model policy (Shree, in brief):** prefer Sonnet 5 agents for creativity and design work, avoid Opus 4.8 there; Opus 4.8 for thoroughness and rigor. **(Shree, follow-up):** the Fable agent writes the actual page copy — "these weaker agents aren't good at coming up with good taglines, hooks, catchy startup lines"; I can reject a lot of the proposals myself; "I love the writing style on the landing page so I don't want regressions there."
>
> **Accent (Shree, follow-up):** "you can mute the aqua brand law closer to charcoal/dark gray. It's not mandatory." All seven designers independently chose to keep full aqua (de-glowed, live/placed-only); the latitude was offered, considered, and not exercised — record this in the synthesis as a deliberate outcome, not an ignored instruction.
>
> **Section-by-section owner MUSTs (from the brief, anchored in direction §4):**
>
> - Nav/logo: icon must not look like a button; icon + text read as ONE designed logo, not a nice icon beside plain Arial text; the nav bar needs much more work and should impress on its own.
> - Hero: fly-in-and-settle is great but jittery — make it smooth; add thin curved paths tracing each fall that draw then undraw, staggered in start time AND duration; the stray "Plan the trip" chip gets a clear purpose or is removed; make hero events draggable ("linear.app-tier landing pages earn it. No further functionality needed, but a user who tries dragging and finds it works gets exactly the right message").
> - "Type it, it lands": no dead cursor — it needs an animation, not real interactivity (AutoML pattern: every component animates its real-world use case); type the prompt out with fluid, intricate tag reveals; prompts more complex, nuanced, real-world; it must NOT run once — cycle type/untype/next; rotate personas weighted primarily toward students, plus school kids, mothers, dads, tech professionals, business people.
> - "One task, three places": right idea, but not clear what is going on — tighten for legibility; add an end state (the moving element must not just disappear); his brace idea (curly brace sweeping across to connect the three views) is explicitly "just my idea! free to design something better!" — the chosen design is an instrument bracket in the brand's dimension-annotation grammar.
> - "Plan without leaving the keys": keys CYCLE through, fading at left/right edges; each key must look like a real MacBook key "with materials so convincing users want to reach out and touch it. Creating convincing, realistic materials is the entire point"; as each key presses, the currently-empty right side shows the actual app responding to that keystroke; transitions extremely smooth, morphing through each other, "landing-page smooth, never a series of stitched-together video clips".
> - "Thursday as a program" (light section): "not well done at all" — no blasting the user with bright white; replace with a rainbow-hue radial gradient keyed to the sweeping clock hand, hues shifting and blending very smoothly in OKLCH; the copy must communicate something real ("saying the app has light mode is not impressive or even acceptable"). Chosen framing: RRULE recurrence performed ("it comes back around"), hues drifting through the product's own curated ladder.
> - Closing: the Start Free button "must not look like a glowing neon sign" — de-glow, dark-editorial; cut the absurd scrolling text above; "if something scrolls there, make it scrolling icons, not random text"; the app component needs a real animation and more effort.
>
> **Standing rules:** brand system (SETTLE tokens, three type voices, --ease-settle, mono-numeral law, honesty instruments — demos show only shipped capabilities) binds throughout per design-brief.md; vanilla JS/CSS/SVG only, no animation libraries; perf budget fold <=500KB, entrances <=1.6s, no scroll-jack; reduced-motion renders everything complete and settled.

**Accent record:** the relaxation toward charcoal/graphite was offered, weighed by all seven designers independently, and not exercised. Aqua stays the single live/placed signal at full strength, severely rationed, CTAs de-glowed, all connective geometry in `--line-dim`. This unanimity is a deliberate design outcome. Do not mute the accent, and do not re-add glow.

### Layout.astro

1. **TF seed, inline in `<head>`, BEFORE any component markup** (this resolves the load-order fact the audit's "shared formatter" arbitration ran into: component scripts are `is:inline` and execute during parse, but motion.js is deferred and executes after parse - so the two symbols inline scripts need at parse time are seeded early, and motion.js extends the same object):

```html
<script>
  window.TF = {
    reducedMotion: matchMedia('(prefers-reduced-motion: reduce)').matches,
    fmtClock: function (d) {
      d = d || new Date();
      var p = function (n) {
        return (n < 10 ? '0' : '') + n;
      };
      return (
        ['SUN', 'MON', 'TUE', 'WED', 'THU', 'FRI', 'SAT'][d.getDay()] +
        ' ' +
        p(d.getHours()) +
        ':' +
        p(d.getMinutes())
      );
    },
  };
</script>
```

2. Load `/src/scripts/motion.js` deferred. Keep font preloads (sentient-300, inter-400, spline-mono-400), skip-link, `html.js` gate.
3. Rename `DayProgram.astro` -> `RecurrenceClock.astro` (contents untouched, stub rename) and swap the import + `<DayProgram/>` -> `<RecurrenceClock/>` in index.astro, so the clock agent later rewrites a file that already exists and the build never breaks.

## (g) Build order and cross-section risks

**Order:** 1) Foundation agent: global.css + Layout.astro (TF seed + motion.js load + DayProgram->RecurrenceClock stub rename + index.astro import swap) + motion.js. Nothing else starts until this lands. 2) Seven section agents in parallel, disjoint files: Nav.astro / Hero.astro / TypeIt.astro / ThreePlaces.astro / Keys.astro / RecurrenceClock.astro / closing suite (Closing.astro + Receipts.astro + Footer.astro + icons/Glyphs.astro). No agent touches another's file; shared needs are already in the foundation contract above. 3) Integration gate: full-page scroll test.

**Integration gate checklist (in addition to each spec's own QA):**

1. Idler payoff end-to-end: drag the hero idler onto the grid, scroll to closing, confirm pre-settled chip + `Every task has its time.` headline; then a fresh session shows the default arrival + default headline.
2. Nav clock and hero honesty clock render the identical `THU 17:42` string at the same minute.
3. Loop adjacency at 1440x1080: scroll Keys->Clock and Clock->Receipts boundaries; never two ambient loops running in one viewport (Clock's 0.4 threshold is the fix; verify, do not assume).
4. Hero entrance recorded at 4x CPU throttle, no frame >20ms.
5. Reduced-motion pass: every section renders complete and settled, no timers scheduled, WAAPI paths guarded via `TF.reducedMotion`.
6. Keyboard-only pass (tab order per specs; nothing decorative focusable) and 360px overflow check.
7. Run the six persona sentences through `SmartParser.testParse()` in-repo and diff against (e).
8. Lighthouse perf >=0.95, a11y 1.0; fold <=500KB.

**Cross-section risks (the ones agents get wrong):**

- The sessionStorage key: `tf-idler-placed`, nothing else. The closing spec's own script block contains the broken underscore spelling.
- `window.TF` load order: component scripts are `is:inline` (run at parse); motion.js is deferred (runs after). Only `TF.reducedMotion` and `TF.fmtClock` are safe at parse time (head seed); every other TF call must sit inside a DOMContentLoaded/IO/timer callback. Never reassign `window.TF`.
- No looping animation may transition `background`/`box-shadow`: lit/pressed states are pre-rendered overlay layers crossfaded via opacity (TypeIt technique, page-wide). One-shot state changes (nav scroll, tp-surface) follow the same pattern per (c).
- The em-dash trap: `SAME OBJECT - SAME TIME`; no `&mdash;`, no em dash anywhere, including aria strings and mono lines.
- Glow creep: `.btn-primary` de-glow lands in foundation; nav keeps its local override as a safety net; nobody re-adds any outer soft glow to any CTA.
- Keys D-cut touches three strings (rail markup, rail aria, stage aria) plus the schedule (self-derives from geometry). Missing one leaves a seven-key label on a six-key rail.
- Rim flash color is always `--aqua` via the shared `.flashable`/`.is-flash` utility; never derive a flash from `--chip-c`.
- The Receipts glyphs must each remain ONE `<path>` (multi-`M` subpaths fine) or the `<use>` draw-in silently breaks.
- Honest numerals: every numeral on the page is Spline Sans Mono (offer times, stage dates, `5 TASKS`/`6 TASKS`, chip cadences, hour labels); the easiest slips are the TypeIt offer string and the Keys stage date.
